# גמ״ח ברגע

פלטפורמת השאלה קהילתית חינמית לישראל, על Cloudflare Workers, D1 ו־R2. כל אחד יכול לפתוח גמ״ח ללא אישור מנהל; הגמ״ח מתפרסם לאחר הוספת המוצר הפעיל הראשון, והאמון נבנה באמצעות דירוגים של שואלים שהשלימו השאלה.

## יכולות עיקריות

- הרשמה באימייל ובסיסמה, אימות אימייל, שחזור גישה ו־TOTP למנהל.
- חיפוש ציבורי, עמודי גמ״ח ומוצר, זמינות, דירוגים וביקורות.
- שמירת מלאי מיד עם בקשה, אישור חלון איסוף, הצעת מועד חלופי, איסוף, החזרה, איחור והארכה.
- רשימת המתנה לפי זמן ההצטרפות והצעה אוטומטית לבא בתור.
- גמ״חים מרובי סניפים, מנהלים והרשאות, יחידות עם מספר סידורי בלתי־ניתן לעריכה ו־QR.
- צ׳אט פרטי, התראות, מועדפים, חיפושים שמורים, בקשות קהילה ותמיכה עם מספר פנייה.
- כתובות משתמש פרטיות מוצפנות; כתובת גמ״ח ציבורית לפי אופי השירות.
- סגירת פלטפורמה בשבת לפי זמני ירושלים, סגירה ידנית וחלונות חג הניתנים להגדרה.
- תחזוקה מתוזמנת, מחיקת חשבון מושהית, שמירת נתוני השאלה פעילה ויומן ביקורת.

## בדיקה מקומית

```bash
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm run check
npm test
npm run dev
```

## משתני וסודות Production

יש לשמור סודות באמצעות `wrangler secret put` ולא ב־Git:

- `RESEND_API_KEY` — מפתח Resend.
- `DATA_ENCRYPTION_KEY` — מפתח ארוך ואקראי להצפנת כתובות פרטיות.
- `TURNSTILE_SECRET_KEY` — מפתח Cloudflare Turnstile.
- `ADMIN_EMAILS` — כתובות מנהל־על, מופרדות בפסיקים.

משתנים רגילים:

- `RESEND_FROM_EMAIL` — למשל `גמ״ח ברגע <no-reply@your-domain.co.il>`; הדומיין חייב להיות מאומת ב־Resend.
- `SUPPORT_EMAIL` — כתובת התמיכה.
- `ENVIRONMENT=production`.
- `JEWISH_HOLIDAY_CLOSURES_JSON` — מערך JSON של `{start,end,message}` בתאריכי ISO עבור חגים.

## פריסה

```bash
npm run check
npm test
npm run db:migrate:remote
npx wrangler deploy
```

אחרי הפריסה יש לבדוק:

1. `/api/health` מחזיר את שירותי הנתונים, האימייל, Turnstile וההצפנה כפעילים.
2. הרשמה ואימות באימייל אמיתי.
3. יצירת גמ״ח ומוצר, בקשה, אישור זמן, איסוף והחזרה.
4. העלאת תמונה, פתיחת צ׳אט, דירוג ופניית תמיכה.
5. חשבון המנהל מוגן בסיסמה ייחודית וב־TOTP.

## גיבוי ושחזור

- D1 מספק Time Travel; לפני שינוי גדול יש ליצור export נוסף ולשמור אותו מחוץ לחשבון ה־Production.
- יש להפעיל Object Versioning על דלי R2 ולשכפל מדי יום לדלי גיבוי בחשבון או באזור נפרד.
- תהליך השחזור חייב להיבדק בסביבת QA, לא לראשונה בזמן תקלה.
- התראות Cloudflare צריכות לכסות חריגות Worker, שגיאות D1/R2, מגבלות אחסון וכשלי cron.

## שחרור בטוח

Workflow בשם `Verify release` מריץ בדיקת תחביר ומבחן עשן מלא על בסיס נתונים נקי בכל Pull Request ובכל push ל־`main`. מומלץ לחבר את `main` לסביבת QA בלבד, לבצע בדיקת קבלה, ואז לקדם את אותה גרסה ל־Production. במקרה של כשל חי יש לבצע Rollback מיידי לגרסת Worker האחרונה התקינה.

## הערה משפטית

האתר מתווך בלבד ואינו צד להשאלה, לפיקדון, למסירה, לשימוש או למחלוקת בין הצדדים. לפני השקה ציבורית יש להעביר את תנאי השימוש ומדיניות הפרטיות לבדיקה של עורך דין ישראלי ולהזין בפאנל את פרטי מפעיל האתר.
